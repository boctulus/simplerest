# Convergencia del core SimpleRest–GoProp

**Estado actual (2026-10-22):** Fase 1 sigue abierta por verificaciones de rutas PSR-4 en Linux y pruebas de integración de base de datos aislada; la puerta de distribución para los cambios de `Schema.php` y `FileUploader.php` sí quedó cerrada con el tag inmutable `boctulus/simplerest` v2.0.2, publicado en GitHub y reflejado en Packagist con referencia `c15d0627afeae9d6bdd0067ee917b8ec7c043d41`. Su ZIP público contiene 273 archivos, 475.250 bytes comprimidos y 1.604.399 bytes expandidos, sin assets frontend. Consumidores limpios con Composer 2.8.5 pasaron instalación `--no-dev --prefer-dist --optimize-autoloader` y comprobación de plataforma en PHP 8.1.14, 8.2.35 y 8.3.36. GoProp resuelve ese tag desde Composer; su repositorio sigue privado y la paridad funcional de la aplicación permanece pendiente.

En `--prefer-source`, el árbol de trabajo del mismo tag contiene 273 archivos y no incluye assets frontend, pero el clon conserva 568.459.924 bytes de `.git`, incluidos blobs históricos bajo rutas de jQuery, Font Awesome y SweetAlert. Por tanto, la exclusión está comprobada para el artefacto Composer `dist` y para los archivos versionados del tag; la instalación desde código fuente aún transporta historial antiguo con esos blobs.

La matriz de decisiones se verificó contra el árbol instalado desde v2.0.2. Las mediciones y pruebas que indican expresamente v2.0.1 son evidencia histórica de ese corte anterior.
**Corte de código:** 2026-10-22.
**Auditoría de partida:** [integración Composer de SimpleRest en GoProp](goprop-composer-integration-2026-10.md).

Este documento es el inventario vivo de decisiones y cambios. No sustituye la auditoría de partida ni presenta como resueltas las diferencias que siguen pendientes de lectura y prueba.

## Reglas de alcance confirmadas

- El paquete Composer del core ya existe: el composer.json raíz declara boctulus/simplerest. El core no debe duplicarse bajo otro nombre o registro.
- Ya existen boctulus/simplerest-pdf, boctulus/simplerest-code-tools, boctulus/basic-acl y boctulus/fine-grained-acl. En la fase de empaquetado se evaluará reducir o cambiar el alcance de estos paquetes y sus manifiestos antes de proponer identidades nuevas.
- En el checkout no se encontró un archivo independiente llamado packagelist. La fuente comprobable local son el manifiesto raíz y los composer.json existentes. Las referencias públicas de Packagist se verificaron por nombre durante esta fase.
- `PdfBase` y `PHPParser` conservan el namespace público existente y se cargan desde sus paquetes respectivos. Los manifiestos de los paquetes agregan sus propios archivos bajo ese prefijo; no mantienen copias dentro del core. El `autoload-dev` raíz mantiene mapas locales solo para trabajar en el monorepo.
- El nombre simplerest-cli no existe entre los paquetes locales inspeccionados. No se crea ni publica como parte de esta fase.
- app/Commands/ sigue siendo propiedad de cada aplicación. El contrato de comando y su registro pertenecen al core; la distribución de implementaciones se decidirá usando los paquetes existentes y evidencia de consumidores.
- La modularización ya tiene una tarjeta vigente en [simplerest-composer-core-packages.md](../to-do/simplerest-composer-core-packages.md). Esta auditoría registra decisiones/evidencia del core y no duplica esa tarea.

Incluye solo `composer.json`, `LICENSE`, `README.md` y `src/`, con cero assets frontend. La compatibilidad está validada en la resolución Composer, no en un envío SMTP.

## Comparación actual de divergencias contra v2.0.2 (2026-10-22)

- El árbol Composer v2.0.2 (ref. `c15d0627afeae9d6bdd0067ee917b8ec7c043d41`) y el árbol actual `goprop/src/framework/` tienen 270 y 274 archivos, respectivamente: 260 rutas comunes, 221 blobs idénticos, 39 divergentes, 14 exclusivas de GoProp y 10 exclusivas de SimpleRest. La comparación normaliza CRLF/LF para no contar diferencias de checkout como cambios de contenido. Cada una de las 39 rutas divergentes aparece en la matriz de decisiones.
- La comparación histórica de 34 diferencias y 22 exclusivas que sigue abajo corresponde a refs anteriores (`996157e76` y `aac5981b`); no representa el corte actual. La matriz de diferencias controladas fue completada contra el tag que GoProp realmente instala.
- El consumidor `--prefer-dist` de v2.0.1 instaló 273 archivos y 1.600.081 bytes expandidos. La inspección del artefacto encontró cero assets frontend: no contiene bibliotecas de UI como jQuery, Tailwind ni Bootstrap. La medición de `--prefer-source` sigue siendo distinta: el checkout Git trae el repositorio completo, por lo que el snapshot de código fuente continúa siendo parte necesaria del proceso de publicación.
- El commit `bdc4019ccb98d84bfd64d699810f9eee4645a6c1` también pasó el empaquetador del core a un snapshot temporal nuevo: `composer validate --strict` aprobó; `composer archive` generó 273 archivos, 1.658.243 bytes expandidos y 449.166 comprimidos, con cero archivos JS/CSS, fuentes o imágenes. El consumidor temporal instaló desde el snapshot con `--no-dev --optimize-autoloader`; `composer check-platform-reqs` pasó en PHP 8.3.36 y `ReflectionClass` confirmó `FileUploader` desde `vendor/boctulus/simplerest`, donde se instanció y configuró. Una petición multipart real al servidor PHP local devolvió HTTP 200, aceptó un archivo `.txt` y verificó su contenido almacenado. La prueba usa el paquete local sin publicar una versión ni modificar tags.
- GoProp `composer.lock` resuelve ahora `boctulus/simplerest` v2.0.2 al SHA indicado arriba. El manifiesto raíz mantiene PHPMailer `^6.9`; el core no lo exige como dependencia de runtime. La instalación y las pruebas focalizadas no demuestran paridad de autenticación, ACL, módulos, persistencia ni workflows completos.
- El tag histórico v2.0.1 no incluía el ajuste de `Schema.php` que fuerza `NOT NULL` en claves primarias. El tag v2.0.2 ya contiene ese cambio y pasó el consumidor limpio con `SchemaBugsTest.php`.
- La protección automática mediante `.htaccess` de GoProp no se copia como efecto lateral del core: las directivas disponibles y permitidas dependen del servidor Apache del host; un archivo generado puede producir errores HTTP 500 cuando `AllowOverride` restringe `Options`. La validación de tipo y origen de upload sí se integra de forma portable; la protección del servidor web queda a cargo de la configuración de despliegue.

## Puerta de salida de Fase 1

El corte actual contra v2.0.2 tiene 39 divergencias con disposición A–E y 24 rutas exclusivas con propietario. La publicación resolvió el bloqueo de distribución de `Schema.php` y `FileUploader.php`; las pruebas focalizadas pasaron con el artefacto etiquetado. La puerta de Fase 1 sigue abierta para verificaciones Linux de mayúsculas PSR-4 y las integraciones GoProp que requieren una base de datos desechable.

Fase 2 reutiliza las identidades Composer existentes: `boctulus/simplerest`, `boctulus/simplerest-pdf`, `boctulus/simplerest-code-tools`, `boctulus/basic-acl` y `boctulus/fine-grained-acl`; no se añadió ningún nombre nuevo. La suite `CommandRegistryComposerPackageTest.php` pasó 8/8 pruebas y 30 aserciones. Los árboles de los tags v1.0.0 coinciden con los directorios locales (46/46 y 3/3 blobs). Packagist P2 aún devuelve 404 para Code Tools y PDF; se conservan sus identidades y repositorios existentes. El core, Code Tools y PDF contienen 273/46/3 archivos y 1.604.399/195.312/5.068 bytes expandidos; no incluyen assets frontend. `vendor/` contiene 23 recursos CSS/map de FPDF, pero no jQuery, Tailwind, Bootstrap ni Font Awesome. El candidato previo `74ac9ea59a637670ed53552443aad96bc0e1c3af` pasó una instalación VCS temporal antes del tag. La migración de GoProp en su rama privada ya resuelve v2.0.2, pero aún requiere validar seguridad, persistencia y workflows completos contra la aplicación.
