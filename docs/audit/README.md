# Documentation audit and evidence rules

## Purpose

The previous documentation grew from a monolithic text file into multiple topic pages. Some pages contain claims that cannot be accepted without source evidence, and some describe proposed or external-framework architecture as though it were part of SimpleRest. This audit rebuilds the maintained documentation from the current implementation.

## Idioma fuente y autoridad editorial

El español es el idioma fuente y predeterminado de la documentación mantenida. Las traducciones se derivan de esas páginas y no evolucionan de forma independiente; ante una discrepancia, prevalece la fuente española. Las páginas vigentes que aún están redactadas en inglés quedan pendientes de migración lingüística y deben revisarse con este criterio al actualizarlas.

La portada canónica es [`../index.md`](../index.md). Solo el contenido enlazado desde ella se presenta como documentación vigente. Los índices anteriores, las páginas temáticas no enlazadas y el material bajo `audit/` o `_internal/` son evidencia de trabajo, historial o pendientes; no son documentación publicable. Si se configura VitePress, esas áreas internas deben excluirse del sitio.

## Source of truth

Use current source code as the primary authority. Trace a behavior through its implementation and configuration. Use tests to establish covered behavior, and runnable examples to establish user-facing instructions. Existing Markdown and the archived `DOC-Simplerest.txt` are discovery material only. They do not validate themselves.

Record the evidence at the level needed for each claim:

| Evidence | What it can establish |
| --- | --- |
| Implementation path and symbol | The behavior or interface exists in this checkout |
| Configuration path and key | The behavior is enabled or altered under stated conditions |
| Test path and case | The tested scenario and its asserted result |
| Example or command run | The exact instruction works in the stated environment |

Do not infer untested behavior from a class name, directory structure, another framework, or an old guide. Mark unclear or environment-dependent statements as unresolved until evidence is available.

## Claim states

- **Verified** — implementation evidence is identified; required configuration and limits are stated. Tutorials also require a successful run of the documented steps.
- **Partial** — part of the claim is confirmed, but scope, conditions, or behavior remain unverified.
- **Unverified** — no sufficient source trace has been completed.
- **Rejected** — the claim conflicts with current implementation or describes a feature that is not present.
- **Historical** — retained to explain prior design or plans; not a statement about current behavior.
- **Application-specific** — supported only by this repository's application configuration or an optional integration; it is not a framework-wide default.

When a source trace finds an ambiguity, keep it **Partial** or **Unverified** and mark the unresolved point explicitly in the claim ledger. Do not use “Verified” to imply that a runtime or end-to-end probe was performed.

### Database re-audit (2026-10-24)

The current `DB::withConnection()` and `DB::withDefaultConnection()` return the callback result from inside `try`; their `finally` blocks only attempt connection restoration. This does not match the earlier claim in the connection ledger that a return from `finally` suppresses the callback exception. `git blame` shows the current control flow in the September 2026 source change; the earlier isolated probe was not repeated. **Classification:** stale audit result relative to this checkout. Update the canonical description to the current source flow; exception behavior remains unexecuted, and an exception raised during restoration could still affect propagation.

`DB::safeSelect()` passes its fifth parameter `$st` as the seventh argument to `DB::select()`, whose seventh parameter is `$tb_prefix`; the output statement reference is not forwarded in the eighth slot. **Classification:** source-level argument-position anomaly; do not promise the output statement handle or normal table-prefix behavior for `safeSelect()` until corrected and verified.

`QueryBuilderTrait::aggregate()` casts the scalar fetch to `int` for every aggregate, including `AVG` and `SUM`; its grouped path casts `fetchAll()` rather than returning rows. **Classification:** source-level return-shape and numeric-precision limitation; do not document decimal or grouped-collection results as preserved.

`SubResourceHandler::getSubResources()` caches results using table, related-table list, tenant identifier, and `pristine`, but not the base query filters or `subquery_conditions`. The same key can therefore reuse a result after query conditions differ in a single process. Its generated aggregation SQL also uses driver-specific functions; only source branches and two direct-relation SQL assertion cases were inspected. `DBRels::getPivot()` can invoke a pivot-scan command when `Pivots.php` is absent, and `DBRelsTest` explicitly lists the complete pivot path as requiring generated files/command infrastructure. **Classification:** relation reads, cache scoping, pivot generation, and per-driver behavior remain partial; no pivot command, database query, or related-resource result was run.

`DB::beginTransaction()`, `commit()`, `rollback()`, and `transaction()` maintain nesting depth per selected connection. Savepoints are selected only when `DB::driver()` returns exactly `mysql`, `sqlite`, or `pgsql`; without them, a nested rollback falls back to rolling back the whole transaction. `transaction()` starts before entering its `try`, commits on normal callback return, and attempts rollback after a caught `Throwable`. SQLite transaction tests and PostgreSQL test cases exist as source but were not run. **Classification:** source-traced API and intended test coverage; runtime transaction behavior remains unverified.

The raw DB facade binds scalar values in `select()`, `insert()`, and `statement()` and applies `Model::addPrefix()` by default or unconditionally on the latter two paths. `query()` aliases `select()`; `update()` and `delete()` alias the unrestricted `statement()` path, and `truncate()` issues a table-wide `TRUNCATE TABLE`. `selectOne()` always requests a single row regardless of its `$only_one` argument. `safeSelect()` passes its statement reference into the table-prefix argument slot. `DB::insert()` also checks an undeclared local `$data` while choosing an explicit primary-key return value. **Classification:** source-level raw-query and write effects; no raw statement was executed, and the anomalies are not represented as reliable return contracts.

`DB::getConnection()` normalizes `mariadb`, `postgres`, and `mssql` into PDO DSN driver names for connection creation, but `DB::driver()` returns the configured value. Other branches compare the unnormalized value to exact driver names, including PostgreSQL float binding, nested-savepoint selection, and subresource aggregation generation. **Classification:** PDO construction aliases are not proof that all driver-specific behavior recognizes those aliases; no alias-configured connection was exercised.

`paginate()` only sets `LIMIT` and an offset calculated as `(page_size * page) - page_size`; it does not compute total rows or return page metadata. Test source asserts offsets for pages 1 and 3, but no database query was run. `aggregate()` casts an ungrouped scalar result to `int` for all supported aggregate names and also casts grouped `fetchAll()` to `int`. **Classification:** source-level pagination and aggregate limitations; numeric precision and grouped result shape are not reliable contracts.

On the `connectTo()`/subresource path with execution disabled, `getSubResources()` still calls `DB::table($relatedTable)` with its default `$connect = true` while reading visible field metadata before returning generated SQL. **Classification:** `dontExec()` on this path does not guarantee that no connection is opened; no connection attempt was made in this audit.
